# Vibe-Code Security Audit

## Purpose

Catch the specific security holes that AI agents create by default — leaked secrets, missing .gitignore rules, client-side-only auth, and exposed system prompts — before the code reaches a public repository or production.

## Activate when

When auditing any AI-generated or vibe-coded project, after a rapid prototyping session, or when code was generated by Codex, Claude Code, Cursor, Copilot, or similar AI tools. Select this capability only when it applies to the request.

## Inputs

- repository tree and git history
- frontend bundle or source
- environment variable configuration
- .gitignore contents
- API routes and middleware
- AI agent prompts or system instructions if present

## Procedure

1. Scan git history (not just HEAD) for committed secrets: API keys, tokens, passwords, connection strings, and .env files. Use pattern matching for common key formats (AWS, Stripe, OpenAI, Firebase, Supabase, database URLs). Check if .env or .env.local was ever committed even if now gitignored.
2. Inspect .gitignore: verify it covers .env, .env.local, .env.production, node_modules, .DS_Store, and any framework-specific secret files. Add missing patterns.
3. Audit frontend source and built bundles for hardcoded secrets: search for API keys, tokens, and credentials in JS/TS source files, environment variable references that resolve client-side (NEXT_PUBLIC_, VITE_, REACT_APP_), and inline fetch calls with Authorization headers containing literal tokens.
4. Check for client-side-only validation: identify forms, API calls, and auth checks that exist only in frontend code with no corresponding server-side middleware or route guard. AI agents frequently skip server-side validation entirely.
5. Review CORS configuration: check if the server allows wildcard origins (*), reflects the Origin header without validation, or exposes sensitive headers. AI-generated Express/Fastify apps commonly use cors() with no options.
6. Assess prompt injection and system prompt exposure: if the app includes AI/LLM features, check whether system prompts are sent to the client, whether user input is concatenated into prompts without sanitisation, and whether API endpoints expose raw model responses including system instructions.
7. Check for AI-generated authentication anti-patterns: JWT secrets stored in frontend, tokens stored in localStorage (XSS-vulnerable), missing token expiry, password comparison with === instead of timing-safe comparison, and admin routes protected only by client-side checks.
8. Produce a prioritised report: for each finding, record Severity (P0-P3), Category (Secret Leak / Missing Server Validation / Prompt Exposure / Auth Anti-pattern / CORS Misconfiguration), File and Line, Impact, and specific Remediation steps.

## Avoid

- Assuming code is secure because it was generated by a reputable AI agent.
- Only scanning the current HEAD without checking git history for previously committed secrets.
- Treating NEXT_PUBLIC_ or VITE_ prefixed variables as safe because they are 'environment variables' — these are compiled into the public client bundle.
- Logging, echoing, or including actual secret values in the audit report.

## Expected outputs

- vibe-code vulnerability report
- leaked secret inventory
- gitignore remediation patch
- client-vs-server validation matrix
- prompt exposure assessment

## Validation

- git history scanned for committed secrets (not just current files)
- .gitignore covers all secret files
- server-side validation exists for every client-side check
- no API keys found in frontend bundles
- CORS configuration reviewed
- Report checks that were not run as unverified.
- Provide evidence references and actionable remediation for failures.
